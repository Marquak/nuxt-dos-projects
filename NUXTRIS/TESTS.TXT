NUXTRIS SELECTOR - 2026-10-20

The Open Watcom build targets V20/80186-compatible 16-bit real mode.
The launcher map reports 18,576 bytes of static DOS memory including
its 2,048-byte stack. Only the launcher and one child game are resident.

In disposable DOSBox-X folders, CHECK.EXE launched the actual SP 1.3
and MP 1.0 executables with /? and returned to the menu after each.
It also showed a missing-MP error when MP_TRIS.EXE was absent. The game
handoff checks returned to VGA mode 12h without failures. Four-plane
VGA captures of the initial menu, moved selection, returned menu, and
missing-file message were decoded and visually checked.

The MP 1.0 help screen displayed NXTNET for the standalone file and
MP_TRIS for the renamed combined-package file.

A second selector test launched the SP and MP automated game builds
without the short /? path. Both entered VGA, installed their input code,
then exited back to the selector. SP reported 144 passed, 0 failed; MP
completed its scripted B-Type menu and wrote its settings file.

The SP 1.3 source still passes its 144 focused checks in DOSBox-X.
The MP 1.0 gameplay code is unchanged from its 0.7.0 preview apart from
the help version label. Earlier MP test results are in SOURCE/MP/TESTS.TXT.
The replacement selector still needs a physical NuXT retest.

PATH FIX - 2026-10-21

The original NuXT run found both child EXEs but reported CANNOT OPEN GAME
FOLDER. The selector now removes the trailing backslash before DOS CHDIR
and, when the game is already in the current folder, can launch it without
changing directories. DOSBox-X checks passed with the game in a named
subfolder and DOS starting from the root: SP launched, MP launched, and
Failed was 0. A forced CHDIR failure launched both games from the current
folder with Failed 0. Removing MP_TRIS.EXE showed the missing-file case with
Failed 0. The replacement still needs a physical NuXT check.
