38 configuration checks and 141 UI/input checks (179 total).

New checks exercise the actual edit dialogs, nested file/folder browser,
Tab/Shift-Tab confirmation focus, default-Cancel discard, preservation of
unsaved fields, ascending/descending menu sorting and config persistence.
Scrollbar endpoints, track paging, pointer-local wheel scrolling and
selection visibility are checked in all three text layouts.
An isolated simulated INT 33 driver checks API detection, signed wheel
counts, ordinary clicks, quick press/release clicks between polls, held
thumb dragging, and consuming the release without launching a program.
These driver tests are not physical mouse-wheel compatibility tests.

font and character/attribute buffer. Clock placement and control bounds
were checked. On 25/43/50-row screens, a selection update still writes
125 cells; unchanged screens/scrollbars write zero cells.

MENU.EXE is byte-identical to 1.4; resident relauncher cost is unchanged.
Config remains version 3; existing menus and joystick/settings data retain
their format. No source changes to DATA.C or MENU.H. The generated inventory
config remains compatible. Physical NuXT testing remains with the owner.
No 86Box runs or changes to live menu/config files.

Earlier release results follow and are not new measurements for 1.5.

NuXT Menu 1.4 - validation, 2026-10-13

DOSBox-X: 38 configuration checks and 75 UI/input checks passed. Includes:
- Legacy v1/v2 migration to v3; custom palette and favourite bits preserved.
- Options roundtrip, invalid saver/timeout/history/calibration rejected.
- Virtual Favourites submenu spans all folders, protects itself from edits,
  consumes no entry slot and returns to Home. Submenu scroll/selection retained.
- 12-hour midnight/noon, 24-hour formatting and BIOS midnight timer wrap.
- Unchanged clock produces no screen writes; wake keys are consumed and
  every saver restores the screen. Joystick action tests cover neutral
  settling, direction repeat, button edges and held-button suppression.
- Existing duplication, browse safety, backup recovery and launch-job tests.
- In 25/43/50 rows, a selection update wrote 125 cells out of 2000/3440/4000;
  unchanged screens wrote zero. Frame/shadow/video comparisons matched.

Private MS-DOS 6.22/QEMU integration:
- EXE, COM, BAT (including a nested EXE) and F9 DOS prompt launch/return.
- EXE arguments /A and 123; batch arguments hello/world; working directory.
- Favourite launch returns to Favourites. Settings survive child programs.
- DOS EXEC out-of-memory failure reports an error and returns to the menu.
- All four saver previews, moving frames and screen restoration inspected.
- Actual one-minute idle timeout blanks the display; Enter wakes without
  opening the selected submenu. Missing gameport fails calibration cleanly.
- Exit confirmation cancels correctly; last-menu startup restores selection.
- Exiting restores C:\APPS, the directory the menu was originally run from.

Controlled free-memory comparison using the same probe EXE and boot:
  Direct launch:     35,628 paragraphs
  EXE through menu:  35,452 paragraphs
  BAT through menu:  35,257 paragraphs
Difference: 2,816 bytes / 5,936 bytes respectively. Earlier launcher overhead
was measured at 31,184 bytes. Environment size, DOS and drivers affect results.
The 2,480-byte assembly EXE includes its 512-byte stack. It shrinks its memory
block before EXEC. The complete UI, clock/savers and screen cache are absent
while the child runs. A nonzero MZ MAXALLOC avoids DOS's special high placement
before shrinking; batch and prompt return paths were checked after this fix.

Build uses Open Watcom warnings-as-errors for the UI, GNU binutils restricted
to 8086 instructions for the supervisor, and Python to write its MZ header.
The UI's small-model data group is within 64 KiB; the directory cache is in a
separate far segment. No compiler runtime remains resident in the supervisor.

No physical NuXT or 86Box tests. Actual gameport/card calibration, timing and
responsiveness remain for the owner to check. New work and integration reports
are under work/nuxmenu-v14; TEST.SH reproduces the DOSBox-X checks in isolation.
Existing user menu/save files were never modified. Earlier results follow;
they apply to those releases, not automatically to this update.

NuXT Menu 1.3 - current validation (2026-10-12)

Built with Open Watcom warnings as errors. Production UI uses a 4 KiB stack;
link map is within the small-model data-segment limit. Shadow screen memory
is allocated separately with _fmalloc and released when NUI exits.

- Legacy version-1 configuration migrates to version 2 with a valid CRC.
- Favourite/pause bits roundtrip and unknown bits are rejected.
- Moving preserves destination order, handles maximum ranks, leaves a
  same-parent move unchanged, and rejects self/descendant destinations.
- Browsing into A&B and cancelling preserves the saved path and saves.
- Favourites span submenus, sort names, and return to the previous menu.
- Duplicate preserves launch fields and flags; cancelling adds nothing.
- Independent copy edits leave the original untouched.
- Favourite does not accidentally add PAUSE to the generated launch job.
- In actual 25, 43 and 50 row modes, selection changed 71 cells; only those
  cells were written. Full screens contain 2000, 3440 and 4000 cells.
- Old highlight clears; frame, shadow and VGA contents match. An unchanged
  frame writes zero cells. Mode changes initialize the entire screen.
- Button coordinates fit without overlap. Appearance Save/Cancel checked.
These are focused regression tests, not a physical NuXT speed benchmark.

MS-DOS 6.22/QEMU with CuteMouse on emulated COM2: real mouse events checked
Back, star/Favourites, Duplicate and its Save/Cancel, explicit Save, Exit,

NuXT Menu 1.2 - validation

Build: Open Watcom, 16-bit real mode, -0 -ms -os -fpc, warnings as errors.
MENU.EXE has a 2 KiB stack; NUI.EXE has a 4 KiB stack. Link maps were
checked for the DOS small-model 64 KiB data-segment limit. No FPU required.

DOSBox: 29 configuration/data checks passed. These cover exact packed
record size, save/load, previous-save backup, CRC failure, truncated files,
recovery when the primary is missing, corrupt backup handling, invalid
parents and cycles, unterminated fields, allowed program extensions, and
DOS path validation. Added CRC check-vector/reference comparisons and
recovery-save tests proving that a valid backup survives a damaged primary
and that ordinary backup rotation resumes after repair. TEST.SH reproduces these in an isolated directory.

MS-DOS 6.22 in a private QEMU image:
- Started MENU from C:\APPS while its two EXEs were in C:\MENU.
- Browsed from the menu directory through the root to a nested directory.
- Added an EXE, edited its label and arguments, and launched it.
- The child logged cwd=C:\APPS\SUB, /A and 123 as separate arguments.
- The menu returned to the same submenu with the selected entry preserved.
- Added and launched a BAT; it received hello and world as arguments.
- Selected 80x43 and 80x50; QEMU VGA supplied 50 rows for both requests.
  The interface uses the actual BIOS row count. Native 43-row timing has
  not been verified on real VGA hardware.
- Changed preset and custom colours; they persisted across child launches.
- Cancelled an appearance edit and recovered the previous display settings.
- Created, entered, reordered and removed an empty submenu.
- Moved a program into a different submenu and found it there.
- Opened the DOS prompt with F9, then EXIT returned to the menu.
- F10 returned to DOS and restored the original C:\APPS working directory.
- /SAFE restored Classic blue and 80x25 without deleting saved entries.
- Cancelling an edited browser filter retained the previous filter.
- An unavailable drive and a missing target produced readable errors.
- Correcting the missing target with F4 allowed it to launch again.

The final build was rerun through SAFE, filter cancellation, unavailable
drive, missing/edited target launch, and exit after adding the conservative
DOS command-line limit and guarding mouse-driver detection.

Memory probe, identical child EXE with heap released:
  Direct launch: 35,637 free paragraphs
  From menu:     33,688 free paragraphs
  Difference:     1,949 paragraphs = 31,184 bytes, about 30.5 KiB
This includes the supervisor and the extra COMMAND.COM used for batch
support. The larger UI process has exited before the child runs. Actual
free memory varies with DOS, drivers, environment size and configuration.

Mouse fixes in 1.1:
- INT 33h release counters replace polling for button-down edges, retaining
  quick clicks across redraws; held buttons do not repeat through menus.
- Single-click opens submenus/browser directories; program double-clicks
  allow one second. A quick second click after opening a folder is ignored.
- Reset the mouse driver after video/font changes, then set text bounds.
- The binary configuration format is unchanged; existing menus still load.

CuteMouse v2.0 alpha 4 in private MS-DOS 6.22/QEMU images, using emulated
PS/2 and Microsoft serial mice (COM2). Input was injected through QEMU
mouse events, not keyboard substitutes or simulated INT 33h responses:
- Single-click Games, Demos and a newly created nested submenu.
  Serial-mouse clicks used 35 ms button holds; PS/2 used 80 ms.
- Right-click returns to parent; double-click does not fall through into
  a child, and holding the button does not traverse nested menus.
- Click the F2 toolbar; browse root, APPS and SUB directories by mouse.
- Double-click an EXE in the browser, add it, double-click to launch, then
  return to the menu with mouse support still working.
- Click top menu entries and bottom toolbar after every screen-layout
  selection: actual 25 and 50 rows. See the 43-row BIOS limitation above.
- F10 restores DOS. Mouse movement/hit positions were verified in text RAM.

COM files use the same COMMAND.COM dispatch path; integration probes used
EXE and BAT targets. Standard VGA was emulated; Trident/Vidsync interaction
and real NuXT behaviour remain to be checked by the user.

No 86Box tests, disk-image delivery, AUTOEXEC/CONFIG changes, physical-disk
writes, or changes to existing games/serial utilities were made.
