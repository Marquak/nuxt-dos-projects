  adds it. Saved DOSBox-X configuration and DOSBOXX.SH corrected accordingly.

Serial fix 0.2, after physical NuXT-to-DOSBox-X feedback:
- Reproduced corruption with the OLD test binary using two DOSBox-X
  directserial instances connected through a local Linux PTY relay. This
  exercises libserial.cpp, unlike the earlier TCP nullmodem tests.
  Both sides timed out: 132/146 rejected frames, 120/152 UART errors.
- DOSBox-X Linux backend clears PARMRK but still consumes FF as an error
  marker. New encoder escapes FF with the existing escape mechanism, leaving
  the original payload and its CRC intact. Both senders must be updated.
- Repeated the same PTY test at 3000/18000 cycles: both completed and saved
  BOB 51 / JON 51, shared pause/resume worked, no rejected frames, UART errors
  or ring overflows. Wire captures contain zero raw FF bytes.
- Shared production encoder tested with every nonce byte value and negative
  shape coordinates: identical decoded payload, no FF left on the wire.
  Prior CRC mutation/loss/bounds checks still pass under ASan/UBSan.
- Detailed UART counters added, including foreground LSR reads.
- The physical USB serial adapter was not opened for these checks. PTYs
  do not reproduce physical line timing or modem control; RTS/CTS was off
  for the PTY check. Physical testing remains necessary.

Serial responsiveness and controls 0.3:
- Reviewed DOSBox-X directserial event and guest MSR polling, and Linux FTDI
  tiocmget: modem-status reads issue synchronous USB control messages.
- New standard-library Python helper relays a localhost transparent socket
  to the physical UART using bounded buffers and kernel hardware flow control.
  No repeated modem-status polling in the relay. No game CRC changes.
- Short DOSBox-X host -> production relay -> PTY -> DOSBox-X joiner check
  at 12000/3000 cycles completed: BOB 51 / JON 50 saved on both sides; zero
  rejected frames, UART errors or receive-ring overflows. Automated Esc opens
  the confirmation and pauses; N cancels it; the other side resumes with P.
- Initial and lost-link automatic cancellation removed by code review.
  Lost state is latched across tick wrap until a valid peer snapshot arrives.
- Real FTDI timing/RTS-CTS performance still requires user testing. The test
  exercises the production byte relay, not physical adapter configuration.
