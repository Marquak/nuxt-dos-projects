NUXTROIDS 1.3 - focused renderer update (2026-10-11)
=================================================
Executable: 28050 bytes
SHA-256: 5d7c3f23ace21dd3e560420a685db4b2aef23944a4c32542a1432111b3de895a

CHANGES
Aligned masks are prepared at startup, merging adjacent byte fragments.
Assembly merges old/new sparse masks for an interior asteroid before VGA
access, so identical pixels cancel and common bytes are touched once.
The cache path uses actual outline bounds, not a fixed 32-pixel border.
A wrapped cache blitter handles seam crossings. Allocation failure retains
the line path. No rules, object limits, physics or audio changes.

FOCUSED CHECKS
67 existing/new checks passed at 640x480 in DOSBox. One added regression
covers the RAM difference merge across shapes, alignments, motion and
rotation. 29 renderer checks each passed at 320x200 and 800x600.
Checks compare every video plane, background restoration and HUD boundaries.
An 800x600 bottom-edge address classification issue was found and fixed.
No extended interactive session, physical hardware or 86Box tests this pass.
Automatic absent-8087 detection and real gamepad timing were not retested.

SCORE UPDATE FIX (1.1)
----------------------
The previous hit path erased and redrew the entire score/best/wave line
with individual pixel calls. It now compares glyphs and XORs only changed
font bits using a seven-row assembly routine. Each row touches at most two
VGA bytes, repeated vertically at the larger modes. Zero masks do not read
or write video memory. Reads load all VGA latches before XOR writes.

Seven added checks cover decimal carries and score limits; byte-exact
comparison of all four HUD planes with the old independent pixel renderer;
unchanged values; shorter messages; every glyph/alignment; clearing to an
empty string; and no playfield corruption. All seven passed in each mode.

Controlled DOSBox normal-core/fixed-1500-cycle benchmark at 640x480:
300 successive score AND best-score increments of 20 points:
  Old whole-line drawing/formatting: 437 BIOS ticks
  New glyph-delta drawing/formatting: 11 BIOS ticks
Approximately 40 times less emulated time for this HUD workload alone.
This is NOT a whole-game FPS speedup or a measured NuXT timing result.
Reproduce using CHECK 1 BENCH. The default CHECK suite does not benchmark.
Game physics, scoring, sound effects and asteroid behaviour are unchanged.

DOS CHECKS

The source includes an optional CHECK.EXE build. Version 1.1 passed 36
checks at EACH of 320x200, 640x480 and 800x600 under DOSBox 0.74-3.
The prior 1.0 build also passed QEMU/FreeDOS checks at 640x480. Those older
QEMU runs and the interactive checks below are historical unless noted.

Coverage:

- Cached integer/8087 geometry agreement within one native pixel.
- 100 assembly line comparisons against a separate pixel implementation,
  across different slopes and octants, plus degenerate and wrapped lines.
- Exact restoration of all four VGA background planes after moving objects.
- Asteroid splitting, scores, all-small-rock expansion, lives and respawning.
- Shot collision, cooldown, buffering a short tap until cooldown expires.
- Wave progression, extra lives, score saturation and stopping with brakes.
- Bounded gameport reads and keyboard fallback when no controller responds.
- Restoring the original timer and keyboard interrupt vectors.

INTERACTIVE EMULATOR RUNS
-------------------------
DOSBox used its actual emulated gameport, fed by a scripted SDL virtual
analog controller. Three-stage centre/up-left/down-right calibration,
button-1 start/fire, left/right steering, button-2 thrust, up-axis thrust,
pause/resume and Escape were exercised. Screenshots were reviewed at all
three resolutions. The 800x600 run also used /N to force integer geometry.
The 320x200 run used /S, and the larger modes used emulated AdLib hardware.

Runs used normal CPU core with fixed 1000 cycles for 320x200 and 1500 for
the larger modes. These settings are workload tests, not V20 clock-speed
measurements. A final 640x480 controller run checked the keyboard-latch
acknowledgement ordering used by the release build.

QEMU runs additionally exercised missing-controller startup, keyboard
movement/fire, repeated pause/resume, mute/unmute, and normal DOS return.
Very short, tightly scheduled HMP key sequences were not reliable in the
automation; controller and complete gameplay input checks used DOSBox.
The AdLib PCM capture was nonzero, with a peak of 10,611 out of 32,767 and
no full-scale clipping. This establishes audio output, not subjective sound
quality on a physical AdLib.

VIDEO AND FPU LIMITS
-------------------
800x600 passed using DOSBox's S3 VBE mode. QEMU's selected VGA BIOS did not
provide a mode accepted by this planar backend and was correctly rejected.
The native Trident 5Bh path is carried over from our working NuXT demos,
but this game still needs bare-metal validation of that path.

/N was tested. The automatic absent-8087 path uses the existing project
probe but was not verified with an absent physical 8087. DOSBox 0.74-3 has
no FPU-disable configuration option, and hiding QEMU's FPU feature flag did
not prevent its emulated x87 instructions from executing. Those attempts
were not valid absent-8087 tests.

No 86Box tests were run. Real NuXT frame rate, ISA VGA memory timing,
physical gameport calibration/noise and original-8087 timing still need
hardware playtesting. Standard BIOS PIT timing is expected on entry;
custom pre-existing timer divisors are not preserved.
